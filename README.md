# ちゃっと放送局 1.6.9

Delta Chatのグループで、収録音声・短い録画動画・音声LIVE・動画LIVEを共有するwebxdcアプリです。1.6.8は、通信応答に応じた疑似LIVEへの自動切替と、小さなコマ撮り映像に対応します。

## 1.6.9の修正

1. **開設前から開いていたメンバーを自動登録**：放送局の開設を受信してオーナーが分かった時点でも、メンバー登録を送ります。開き直す必要はありません。履歴の読み込みが終わる前の送信や、同じ登録の二重送信を防ぎます。送信に失敗した場合は待ち時間を設けて再試行します。
2. **端末に合った機器エラー案内**：Delta Chat内では、端末設定でのDelta Chatへのカメラ・マイク許可と、Delta Chatの設定・バージョン確認を案内します。ブラウザデモでは、ブラウザのサイト設定と端末側の許可、必要な場合はHTTPS／localhostを案内します。
3. **LIVE表示の待ち時間を方式別に分離**：リアルタイムは配信案内の受信が約6〜7秒途絶えると表示と視聴を停止します。疑似LIVEは送信間隔に合わせた長めの待ち時間（送信間隔10秒の場合は約55秒）を維持します。終了通知後の残り音声は従来どおり再生します。

1.6.8のコードで3点を再現し、修正後のメンバー登録・管理画面表示・履歴読み込み・送信失敗後の再試行・端末別エラー案内・方式別の待ち時間を模擬端末で確認しました。既存の疑似LIVEの自動切替・音声再生・送信容量・権限解除なども自動テスト済みです。Delta Chat実機での確認は未実施です。

HTML・Word・PDF操作マニュアルも1.6.9用に更新しました。新たな配布では全員が1.6.9の同じ添付を使ってください。

## 最初に使う

1. 担当者がアプリをDelta Chatのグループへ送ります。全員が**同じ添付メッセージ**から開きます。
2. 開設担当者を決め、その人が「放送局を開設する」を押します。放送局名を1〜40文字で入力して開設します。
3. メンバーが同じ添付を一度開き、オーナーが「管理」から配信する人を許可します。開設前から開いたままの端末も、開設を受信すると自動登録され、開き直す必要はありません。
4. 許可された人が収録やLIVEを配信し、メンバーが▶から聴く・見る操作をします。

同じアプリ名でも、別に添付したコピーは別の放送局です。上部の局名とオーナーを確認してください。名称は本人確認や公式性を保証しません。

| 役割 | 操作 |
|---|---|
| メンバー | 収録再生、LIVE視聴、受信完了した収録の書き出し |
| 配信者 | メンバーの操作に加え、収録・LIVE配信、自分の収録の削除 |
| オーナー | 配信者の許可・解除、放送局名変更、履歴取り込み |

解除が端末に届くと、新規投稿と送信待ち中の投稿を止めます。解除前に受信した放送は残ります。設定の共有には通信時間が必要です。意図しない人がオーナーになった場合、既存の局で権限を上書き回復する機能はありません。担当者が新しい添付で開設して移行します。

## 収録音声と録画動画

「配信する」を開き、タイトルを入力します。音声は丸い録音ボタンで開始・終了するか、「または音声ファイルを選ぶ」から指定します。録画動画は「録画動画ファイルを選ぶ」から指定します。試聴・プレビューで確認し、「配信する」を押して送信完了まで待ちます。

- 収録音声：最長3分・約3MBまで。
- 録画動画：60秒・約5MBまで。MP4のH.264映像・AAC音声をお試しください。圧縮・編集は選択前に行います。
- 視聴側は、全件が届いて▶になると再生できます。%表示は受信中です。
- 「この放送をリピート」は同じ収録を繰り返します。音声・動画で共通、自分の端末だけの設定です。アプリを開き直すとOFFに戻ります。LIVEと録音の試聴は対象外です。
- iPhone・iPadでは再生終了時の再開を補完します。再開できない案内が出た場合は、▶で手動再生し、リピートをもう一度選びます。iPhone実機での解消は未確認です。

## LIVEを配信する

1. 「ライブ」でタイトルと「音声LIVE」または「動画LIVE（実験）」を選びます。動画では前面・背面カメラも選べます。
2. 接続方式を選びます。通常は「自動（通信応答で切替）」からお試しください。
3. 「ライブ開始」を押し、配信する端末のマイク・カメラ利用を許可します。
4. 視聴者は同じ1.6.9の添付を開き、LIVE欄の▶を押します。視聴だけならマイク・カメラの許可は不要です。
5. 終えるときは配信側の「終了」を押します。視聴側の「停止」は自分の視聴だけを止めます。

全員がアプリを前面に表示してください。最大10分で自動終了します。画面ロックやバックグラウンドによる音声処理の停止は、自動切替では解決できません。

### 接続方式

| 接続方式 | 動作 |
|---|---|
| 自動 | チャット経由で開始。今回の配信について視聴端末とのLIVE通信の往復応答が続けばリアルタイムへ切替。約6秒途絶えれば疑似LIVEへ戻る |
| チャット経由の疑似LIVE | 通常のチャット更新で音声・画像を送る方式に固定 |
| リアルタイム固定 | 従来のLIVE経路に固定。疑似LIVEへ自動切替しない |

「インターネット接続あり／なし」の完全な判別ではなく、端末間のLIVE通信が使えるかによる切替です。外部回線を切っても直接通信が続く場合はリアルタイムを維持します。視聴者がいなければ到達を確認できないため、自動では疑似LIVEになります。切替時に短い音の途切れが生じる場合があります。

チャット経由でしか応答しない視聴端末が分かった場合も、疑似LIVEへ戻します。疑似LIVEは1.6.8以降が必要です。配布先では版をそろえ、全員が新版の同じ添付を使ってください。

### 疑似LIVEの音声とコマ撮り映像

音声は16kHzを0.25秒ずつADPCM圧縮し、端末の送信間隔を守ってまとめて送ります。動画では、最大160×120・JPEG約9KB以下の最新の静止画を、音声のまとまりに1コマ添えます。通常は2〜10秒以上ごとの更新です。滑らかな動画ではなく、音声との厳密な同期もしません。リアルタイム動画は最大320×240・約2コマ／秒です。

送信間隔が10秒の端末では、まとめる待ち時間に配送と再生待ちが加わります。「必ず数秒で届く」とは保証しません。送信が追いつかない場合は古い音声を省略し、待ちデータが際限なく増えないようにしています。端末の送信間隔が30秒を超える場合や容量不足の場合は、疑似LIVEを開始できません。

### 終了通知と一言

「終了」ではマイク・カメラを止め、疑似LIVEの最後の音声を送った後に、開始時の配信者名とタイトルを付けてチャットへ終了通知を出します。送信待ちが終わるまで画面を開いたままにしてください。視聴側は、届いている残りの音声を再生してから終了します。

強制終了・電源断・通信断では、最後の音声や終了通知が届かない場合があります。送信失敗の表示が出たときは、必要に応じて通常のチャットで終了を伝えます。

リアルタイムLIVE中は配信者へ80文字までの「一言」を送れます。到着確認は端末の応答で、本人の既読ではありません。一言は履歴JSONには入りません。疑似LIVE中は一言欄を表示しません。

## 疑似LIVEのメールと保存

**疑似LIVEで送った音声・画像は、通常のチャット更新として通信履歴に残ります。** リアルタイムLIVEとは異なります。放送一覧の収録や履歴JSONには含めません。履歴が残ることと、過去の疑似LIVEを収録として再生できることは別です。

| 送信間隔の例 | 10分間の音声・画像更新の目安 |
|---|---|
| 10秒ごと | 約60回 |
| 2秒ごと | 約300回 |

開始・終了・視聴応答の更新も加わります。更新がまとめられることがあるため、実際のメール通数とは一致しません。アプリデータは、音声だけで約0.65MB／分、画像込みで約0.7〜1.1MB／分が目安です。メール等の通信上の付加分は別です。

- 放送局アプリからINBOXのメールを直接削除することはできません。削除や保存期限は、Delta Chat本体の対応機能やメールサーバー側で管理します。
- INBOXからメールを削除しても、Delta Chat端末内の更新履歴を消したことにはなりません。
- TinyBoxでは、配信用メールボックスの保存期限を管理担当者が検討してください。受信直後の削除は、同一アカウントの別端末や未受信端末が受信できなくなる可能性があります。「既読」は全端末の受信完了ではありません。
- 「消えるメッセージ」は放送局の添付も削除対象になり得ます。更新データだけを消す目的で短時間に設定しないでください。

## 外部回線なしで使うとき

外部インターネットがなくても、TinyBoxなどを通じて**通常のチャット更新を端末間で配送できる環境**が必要です。Wi-Fiに接続するだけで配送できるわけではありません。

1. 外部回線を切り、通常のグループメッセージが別端末へ届くことを確認します。
2. 「チャット経由の疑似LIVE」固定で音声、次にコマ撮り映像を確認します。
3. 「自動」で方式と受信数を確認します。直接通信が続く場合は、リアルタイムのままで正常です。
4. 外部回線を切ったままTinyBoxと全端末を再起動し、新たに配信して受信できるか確認します。

一度オンラインで接続した後の継続と、オフラインからの開始は別に検証してください。自動切替は、メールサーバーの設定や起動を代わりに行うものではありません。

## 受信が進まないとき

収録音声・録画動画が71%などのまま止まった場合は、視聴側で「不足分の再送を依頼」を押し、配信元で「再送」を押してもらいます。依頼は1分以上空けます。両側の画面を開いたまま待ち、視聴側で▶から再生できるか確認します。

再送には不足分の元データが必要です。配信元では送信前に元データを保持し、保存機能が使える環境では端末にも保存します。「この画面を開いている間だけ保持」と表示された場合は、復旧まで閉じないでください。元データがない場合は元ファイルを新しい放送として配信し直し、受信確認後に古い未完了放送を削除します。

疑似LIVEの音切れを後から再送する機能ではありません。「ライブ通信を再接続」も収録データの再送とは別です。

LIVEが届かない場合は、同じ添付・配信許可・接続方式と、配信側の送信数／視聴側の受信数を確認します。開始通知だけでは音声・映像の到達確認になりません。「音声を再開」「映像を再開」を試します。リアルタイムだけが不調なら再接続し、疑似LIVE固定でも確認してください。

## 局名と履歴の引き継ぎ

局名はオーナーが「設定」→「放送局名」→「放送局名を保存」で変更します。同じ添付を開くメンバーに同期され、チャット添付の補助表示にも送ります。表示位置はDelta Chatの実装によって異なり、長い名前は省略されます。

新版への移行は、旧版の「設定」→「放送一覧を書き出す」でJSONを保存し、新版で開設したオーナーが「放送一覧を取り込む」で共有します。送信・取り込み中は画面を開いて待ち、他端末で受信完了と再生を確認してください。

JSONには受信完了済みの音声・動画本体、タイトル、元の配信者名、日時が入ります。未完了・削除済みの収録、LIVE・疑似LIVE、一言、配信許可、リピート設定は入りません。JSON全体は64MBまでです。同じ履歴の二重取り込みは省略し、移行先で削除済みの放送も復活させません。

配布用フォルダーから旧ファイルを削除しても、Delta Chatへ送信済みの添付は別に残ります。チャット内の旧添付は移行完了を確認してから整理してください。

## index.html単体で試すデモ

index.htmlをChromeまたはEdgeで直接開くと、Delta Chatを開かずに画面操作を試せます。ブラウザや設定によって、カメラ・マイク・保存・別タブ共有など一部の機能を利用できない場合があります。

プレビュー内の「別の視聴タブを開く」から、同じブラウザの別タブで視聴を試せます。「タブを複製」ではなく、このリンクを使ってください。ブラウザデモとDelta ChatはLIVEでつながりません。別のPCへの配信機能ではありません。

## 確認済みの範囲

模擬端末で、今回の配信に対する往復応答の確認、自動切替、応答途絶と混在視聴端末による復帰、配信権限解除、送信待ち上限、容量上限、古い・重複データの拒否、最後の音声と終了通知を確認しました。

Chromeでは、仮想マイク・カメラで、リアルタイムAPIなしの音声・160×120以下のJPEG送受信、スマートフォン幅の表示、終了操作を確認しました。従来の収録送信・権限・リアルタイム動画・一言・終了通知も自動テストしました。

**Delta Chat実機間、TinyBoxのオフラインからの起動、iPhone、人数を増やした運用、長時間の配送速度は未確認です。** 実際に使う端末と人数で事前に確認してください。
